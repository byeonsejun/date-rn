# 한국 지명·시설명의 CJK(일본어/중국어) 표기 기준

> **목적**: POI 데이터(`park.json` `p_park_en`, `culturalSpace.json` `FAC_NAME_en`,
> `dodreamgil.json` `CPI_NAME_en`)와 구 이름(`entities/location/model/data.ts`)의
> 다국어 번역을 **일관된 규칙**으로 하기 위한 기준 문서.
>
> 1차 대상은 일본어(`_ja`, 약 2,600건)이며, 이후 중국어(`_zh`) 확장 시에도 이 문서를 기준으로 한다.
> 대량 번역(park 132 / culturalSpace 1,028 / dodreamgil 1,329)에서 케이스별 판단이 흔들리지 않도록,
> **접미사(공원/도서관 등) 대응표 + 고유명사부 처리 우선순위**를 명시한다.

---

## 0. 최상위 원칙

한국의 지명·시설명은 대부분 **한자어(漢字語)**이므로, 일본어/중국어는 원칙적으로
**대응 한자로 표기**하고, 한자로 환원되지 않는 부분(순우리말·외래어)만 음차(가타카나 등)한다.

우선순위(위에서부터 적용):

1. **정식 한자 표기가 존재/명확** → 그 한자를 그대로 쓴다. (예: 中区, 南山公園, 市立図書館)
2. **한자어 접미사 + 고유명사부** → 접미사는 §2 대응표대로 한자, 고유명사부는 §3 기준으로.
3. **순우리말·유래 불명 고유명사** → 한국어 발음의 가타카나 음차(일본어) / 병음 기반 음역(중국어).
4. **외래어(영어 등)** → 원어 표기 유지 또는 관용 가타카나.

> 판단이 애매하면 **더 보수적인 쪽(원 발음을 보존하는 음차)** 을 택하고, 아래 §5에 케이스를 추가한다.

## 2-1. 「길」 종류 세분 대응표 (dodreamgil 확정)

`dodreamgil.json` `CPI_NAME`의 「길」은 **접미어의 의미대로 일본어로 의역**한다(가타카나 음차 금지).
지명부는 §1·§3 규칙(한자어=한자, 순우리말=음차) 조합. 예: `南山둘레길` → `南山めぐりの道`.

| 한국어 「길」 | 일본어 | 비고 |
| --- | --- | --- |
| 둘레길 | めぐりの道 | 周遊路보다 자연스러움 |
| 자락길 | ふもとの道 | |
| 숲길 / 숲속길 | 森の道 | 무장애숲길 → バリアフリー森の道 |
| 오솔길 | 小道 | |
| 나들길 | お出かけの道 | |
| 마실길 / 산책길 | 散策の道 | 산책길도 동일 처리 |
| 물길 | 水辺の道 | |
| 하늘길 | 空の道 | |
| 산책로 | 散策路 | (로=路) |
| 옛길 | 古道 | |
| 고갯길 | 峠道 | 고개(단독) → 峠 |
| 강변길 / 천변길 | 川辺の道 | |
| 일반 ○○길 | ○○の道 | 초록길 → 緑の道, 문화길 → 文化の道 등 |

**「길」이 道가 아닌 경우 (오탐 — の道 금지):**
- **도로명주소** `○○로 N(가/나/다/라)길`: 도로 체계이므로 「の道」로 옮기지 않는다. 잠정 규칙 = **로→路(한자어면 한자), 번호+가/길 = 가타카나 음차**. 예: `統一路18ナギル`, `木洞中央本路7街ギル`. (전용 확정은 §5 로그)
- **갈림길**: 分かれ道 (분기점 의미, の道 아님).
- **능선길 / 내리막길 / 오르막길**: 尾根の道 / 下り道 / 上り道.
- **뒷길 / 앞길**: 위치어(裏道/裏手, ～前). の道 아님. 예: `서경대뒷길` → `西京大裏道`.
- **마을안길**: 集落内の道.
- **어두 「길」 = 吉** (道 아님): `길음(吉音)`, `길상사(吉祥寺)`, `길동(吉洞)` 등 지명·시설 형태소.
- **인명 「길」**: `윤봉길 → 尹奉吉` (배치 2 이후 등장). 절대 道 아님.

## 3. 고유명사부 처리

### 3-1. 지명 유래(한자 환원 가능) → 한자
- `남산공원` → `南山公園`
- `청계천` → `清渓川`
- `북서울꿈의숲` → `北ソウル・夢の森`(北=한자, 서울=ソウル, 꿈의숲=순우리말→「夢の森」의역 허용, §3-3 예외)
- `서울` 은 고유어이므로 항상 `ソウル`.

### 3-2. 인명·왕조·역사 유래 → 정식 한자
- `세종` → `世宗`, `이순신` → `李舜臣`, `경복궁` → `景福宮`.

### 3-3. 순우리말 고유명사 → 가타카나 음차 (원칙) + 의미 병기 없음
- 한자로 환원되지 않는 순우리말은 **한국어 발음 가타카나**로 음차한다.
  - `하늘공원` → `ハヌル公園`(하늘=순우리말, 「空」로 의역하지 않음)
  - `노을공원` → `ノウル公園`
  - `한밭` → `ハンバッ`
- 단, **관용적으로 의역이 정착**했거나 브랜드가 의미 전달을 의도한 경우 의역 허용(§3-1 「꿈의숲」 예).
  판단이 갈리면 **음차 우선**(원 발음 보존). 의역을 택하면 §5에 근거를 남긴다.

### 3-4. 두드림길(브랜드 고유명) → `トゥドゥリムキル`
- `두드림길`은 서울시 무장애 자락길 브랜드명. 의미 번역 대신 **가타카나 음차** `トゥドゥリムキル` 고정.
- `dodreamgil.json`의 `CPI_NAME`은 코스명이 아니라 **경유지명**(예: `서울대학교 버스정류장`)이며, 위 §1~§3 규칙을 그대로 적용한다.
  - `서울대학교 버스정류장` → `ソウル大学バス停`
  - 경유지가 순우리말이면 §3-3.

## 4. 외래어·영어명

- 영어 원어명이 정착한 시설 → **원어 유지 또는 관용 가타카나**.
  - `DDP(동대문디자인플라자)` → `DDP（東大門デザインプラザ）`
  - `아트센터` → `アートセンター`, `센터` → `センター`, `타워` → `タワー`, `플라자` → `プラザ`
- 알파벳 약어(`DDP`, `SM` 등)는 그대로 둔다.

## 5. 애매 케이스 결정 로그 (번역 중 갱신)

번역 중 규칙만으로 판단이 안 되는 케이스는 여기에 **결정 + 근거**를 남겨,
같은 이름이 다른 파일/구에서 다시 나올 때 일관되게 처리한다.

| 원문 | 채택 표기 | 근거 |
| --- | --- | --- |
| (예) 꿈의숲 | 夢の森 | 브랜드가 의미 전달 의도, 일본 관용상 「夢の森」 자연스러움 |
| 노원구 | 蘆原区 | **정자(蘆) 채택**(신자체 芦 아님). 한국 지명 한자는 정자 보존이 원칙(鍾路区·龍山区와 동일 계열). 일본어 위키피디아 표제어도 蘆原区. |
| 광진구 | 広津区 | **신자체(広) 채택**(정자 廣 아님). 노원(蘆 정자)과 달리 이 글자는 일본어 위키 표제어가 신자체 広津区를 씀 → 구별 정자/신자체 혼재는 "일본어 위키 표제어 형태를 따른다"는 기준(§1)으로 통일. 중국어(_zh)는 별도(간체 广津区). |

## 7. 중국어(_zh) 확장 — 확정 규칙

> **상태**: 규칙 확정(2026-08-02). 일본어(§1~§6) 구조를 그대로 재사용하되,
> 자형은 **간체자(简体字)**, 음차 수단이 없는 언어 특성상 **의역 우선**이 핵심 차이다.
> 필드명: 구 `location_zh`, POI `p_park_zh`/`FAC_NAME_zh`/`CPI_NAME_zh` → 모델 `titleZh`.
> UI 카피는 `locales/zh.json`. 폴백은 §7-6.

### 7-0. 중국어 최상위 원칙 (일본어와의 차이)

일본어는 순우리말을 **가타카나 음차**했지만, 중국어에는 표음 전용 문자가 없다.
따라서 우선순위가 다르다:

1. **정식 한자 표기 존재/명확** → 그 한자의 **간체자**. (예: 南山公园, 清溪川)
2. **한자어 접미사 + 고유명사부** → 접미사는 §7-2(간체), 고유명사부는 §7-3.
3. **순우리말·유래 불명 고유명사** →
   - (1순위) **의역**: 뜻이 명확하면 의미로 번역. 예 `하늘공원` → `天空公园`.
   - (2순위) 의역 어려운 순수 고유명사 → 한국 표준 발음 기반 **음역 한자**(관용 음역 있으면 그것).
   - 가타카나식 음역 불가 → **의역을 항상 먼저 시도**하고, 정 안 되면 발음 기반 한자.
   - 애매한 케이스는 **배치 단위로 모아** 확인 요청(개별로 멈추지 않음).
4. **외래어(영어 등)** → 원어 유지 또는 관용 중국어 표기.

> 일본어 §3-3(음차 우선)과 정반대로, 중국어는 **의역 우선**이다. 이 점을 혼동하지 말 것.

### 7-6. 폴백 정책 (zh, 코드 측)

일본어 §6과 동일 구조. 중국어 사용자에게도 한국어 원문보다 영어가 유용:

```
zh: titleZh ?? titleEn ?? title(ko)
```

`getDistrictLabel` / `getPoiDisplayTitle`에 `zh` 분기 추가. `getCategoryLabel`은 `zh.json` 키 기반 자동 대응.

### 7-7. BFF(weather) 연동 — 프로덕션, 배포 게이트

- RN `WeatherProxyBody.lang`은 `SupportedLanguage` 유니온이라 `zh` 추가 시 자동 포함 → RN이 `lang: "zh"` 전송.
- **OpenWeather `lang` 코드**: 한국어=`kr`(예외), 일본어=`ja`, **중국어 간체=`zh_cn`**(예외), 번체=`zh_tw`.
  BFF가 `zh` → `zh_cn` 매핑을 해야 `description`이 중국어로 내려온다.
- BFF는 **프로덕션(웹 레포)**이므로 배포 전 멈춤 → **curl 게이트**(일본어 때와 동일).
  BFF 미대응 상태에서 ZH 토글 시 날씨 `description`만 영어로 폴백(크래시 아님) — UI/데이터 번역은 정상.
